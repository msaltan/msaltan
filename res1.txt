Evet, dosyaya baktım. Buradaki **Flux/KuboCD problemi aslında HelmRelease'ın kendisinden çok `keycloak-config-cli` post-upgrade Job'ının fail olması**.

HelmRelease şu anda sürekli aynı noktada takılıyor:

> `post-upgrade hooks failed ... Job/keycloak-main-keycloak-config-cli status: 'Failed'`

ve **285 kez upgrade failure** oluşmuş. 

### İlk teşhis

Senin HelmRelease'te:

* Keycloak: `26.1.3`
* Bitnami chart: `24.4.11`
* external PostgreSQL kullanılıyor
* `keycloakConfigCli.enabled: true`
* config CLI image: `okdp/sandbox-images/keycloak-config-cli:6.4.0-debian-12-r0`
* `master.json` üzerinden bütün realm/client/user konfigurasyonu import ediliyor.  

Helm upgrade sırasında önce StatefulSet vb. güncelleniyor, sonra Job silinip tekrar oluşturuluyor:

```text
12:05:47  Patched StatefulSet
12:05:48  starting delete resource: Job/keycloak-main-keycloak-config-cli
12:05:48  Created resource via patch
12:10:23  upgrade failed
```



Dolayısıyla **Flux veya KuboCD'nin kendisi ilk şüpheli değil**. Flux sadece başarısız Helm upgrade'ı tekrar tekrar deniyor.

Bitnami chart'ın `keycloakConfigCli` mekanizması zaten `post-install/post-upgrade/post-rollback` Helm hook olarak çalışıyor. ([GitHub][1])

## Şimdi en önemli şey

HelmRelease çıktısı **Job'ın neden fail olduğunu söylemiyor**.

Bunu Kubernetes'ten almamız gerekiyor.

Şunları çalıştır:

```bash
kubectl -n keycloak get job keycloak-main-keycloak-config-cli -o wide
```

sonra:

```bash
kubectl -n keycloak get pods \
  -l app.kubernetes.io/component=keycloak-config-cli \
  -o wide
```

ve özellikle:

```bash
kubectl -n keycloak logs \
  job/keycloak-main-keycloak-config-cli
```

Ayrıca:

```bash
kubectl -n keycloak describe job keycloak-main-keycloak-config-cli
```

ve:

```bash
kubectl -n keycloak get events \
  --sort-by='.lastTimestamp' | tail -50
```

**Bana özellikle `kubectl logs job/...` çıktısını gönder.**

Çünkü şu anda birkaç olası kök neden var ve log olmadan hangisi olduğunu söylemek doğru olmaz.

### Benim en güçlü şüphelerim

#### 1. Keycloak hazır olmadan config-cli çalışıyor

Job şu URL'ye bağlanıyor:

```text
http://<keycloak-headless-service>:8080/
```

Bitnami'nin Job template'i de config CLI'yi Keycloak headless service üzerinden çalıştırıyor. ([GitHub][1])

Senin Keycloak ise external PostgreSQL kullanıyor:

```text
postgresql-instance-rw.cnpg-system.svc.cluster.local:5432/keycloak
```



Dolayısıyla Keycloak'ın gerçekten `Ready` olup olmadığını kontrol etmek önemli:

```bash
kubectl -n keycloak get pods
```

ve:

```bash
kubectl -n keycloak logs statefulset/keycloak-main --tail=200
```

---

#### 2. `master.json` içindeki configuration bir noktada Keycloak 26 ile uyumsuz

Sen oldukça büyük bir config import ediyorsun:

* users
* realm roles
* clients
* service accounts
* client scopes
* protocol mappers

Örneğin:

```json
"roles_map_to_groups"
```

mapper'ı ve `groups` claim configuration'ı var. 

Ayrıca birden fazla service account client'ı tanımlanmış:

```text
svc-trino-polaris-writer
svc-trino-examples-writer
svc-polaris-api-admin
svc-spark-etl-polaris-writer
```



Bunlardan biri config-cli import sırasında hata veriyor olabilir.

---

#### 3. Daha da önemlisi: Config CLI image'ını override etmişsin

Chart:

```text
keycloakConfigCli.image
```

için normal Bitnami image'ını kullanmak yerine:

```text
quay.io/okdp/sandbox-images/keycloak-config-cli:6.4.0-debian-12-r0
```

kullanıyor. 

Bu nedenle **6.4.0 image'ının gerçekten hangi `keycloak-config-cli` versiyonunu içerdiğini de kontrol etmek isterim**.

Çünkü upstream chart'ın güncel tarafında 6.4.x kullanılıyor olsa da senin image'ın `r0` custom/sandbox image'ı. Upstream chart'ın image'ı ile birebir aynı olmak zorunda değil. ([GitHub][2])

### Flux/KuboCD tarafında şu anda değişiklik yapma

Bence şu aşamada:

```bash
flux suspend helmrelease keycloak-main -n kubocd-system
```

gibi bir şey yapıp sistemi sakinleştirebiliriz, ama **önce Job logunu görmek daha doğru**.

Çünkü şu an Flux sürekli:

```text
upgrade
→ config-cli Job
→ Job failed
→ HelmRelease failed
→ retry
→ upgrade
→ ...
```

döngüsünde.

Nitekim dosyada `Upgrade Failures: 285` görünüyor. 

**Bana şu tek çıktıyı gönderirsen kök nedeni büyük ihtimalle direkt bulabiliriz:**

```bash
kubectl -n keycloak logs job/keycloak-main-keycloak-config-cli
```

İstersen ardından sana **HelmRelease values'ını Flux/KuboCD yapısını bozmadan düzeltilmiş haliyle** verebilirim.
